# Decisions

One line each: date — decision — reason.

- 2026-10-14 — Product name is **Fieldly**, `APP_KEY` is `fieldly:` — the spec's working title is "rename freely" and the repo is `fieldly`.
- 2026-10-14 — TypeScript pinned to 6.0.3, not 7.x — `typescript-eslint` 8.71 supports `<6.1`; TS 7 would break linting.
- 2026-10-14 — React Router 8 (`react-router` package, `HashRouter`) instead of `react-router-dom` — in v7+ `react-router-dom` only re-exports `react-router`.
- 2026-10-14 — Tailwind CSS v4 via `@tailwindcss/vite`, theme colours as CSS variables mapped with `@theme inline` — v4 is current stable and needs no PostCSS config.
- 2026-10-14 — Deploy workflow uses the current majors: checkout@v7, setup-node@v7, setup-python@v7, upload-pages-artifact@v5, deploy-pages@v5 — §6.3 asks to bump to latest majors.
- 2026-10-14 — `build` also runs `tsc --noEmit` — Vite does not type-check, and `strict: true` should be enforced in CI.
- 2026-10-14 — Exact integers below 1e5 print exactly (12345 → "12345"); everything else goes to 3 significant figures — §7.4 says "integers printed as integers", and rounding counts like 1024 to 1020 would be wrong.
- 2026-10-14 — Negative numbers use the Unicode minus "−" in text and "-" inside KaTeX — typographically correct in both places.
- 2026-10-14 — Each challenge type is split into a React-free `logic.ts` (schemas, `resolveConfig`, scopes) and a component — the Node validator must import the logic without React or DOM.
- 2026-10-14 — Challenge `config` holds expression strings; each type's `resolveConfig` turns them into numbers/text before the component sees them — §9.1 says the component receives "templates and expressions already resolved".
- 2026-10-14 — `subject.yaml` gains optional `background` (free-text prerequisites such as "algebra") and `tools` — §16 lists non-subject prerequisites that cannot be subject ids.
- 2026-10-14 — Lesson `prerequisites` default to the previous lesson in the subject (crossing unit boundaries) — §16 says "previous lesson in the unit"; the first lesson of a unit then points at the end of the previous unit.
- 2026-10-14 — "Standard difficulties are non-decreasing" (§2.5) is enforced as a validator error — it is stated as a rule, not a guideline.
- 2026-10-14 — Lesson YAML is parsed with merge keys (`<<: *anchor`) enabled — lets authors reuse blocks without copy-paste.
- 2026-10-14 — A lesson file with validator errors is emitted but marked unavailable ("Coming soon") in the index — `content:build` fails anyway in CI; in watch mode the rest of the site keeps working.
- 2026-10-14 — Lesson player, review, profile and settings are lazy route chunks — keeps mathjs, KaTeX and Markdown out of the initial JS budget (§4).
- 2026-10-14 — `AttemptState` gains `sequence` (ordered step ids incl. inserted steps), `factSteps`, `firstInSubject`, `ratingsBefore`, `lessonVersion`, `skippedSteps`, `startedAt` — §12's shape cannot place inserted steps or show rating change per concept without them.
- 2026-10-14 — Partial answers (first wrong pick, hints opened) are saved immediately — a refresh must not reset attempts or hints.
- 2026-10-14 — Remediation is inserted after 2 misses when its `remediates` is one of the two missed steps or the next core step — §2.1 says "for the missed step"; the next-step case lets r1 prepare s3 after misses on s1–s2.
- 2026-10-14 — When a step has no `uses` and no authored `buildsOn`, the hint ladder has 2 tiers and `partial` still counts as tier 3 for scoring — `partial` is the half-solution tier whatever its position.
- 2026-10-14 — Variant selection uses the spec's numbers unchanged: at the initial rating 1000, `easier` (p ≈ 0.70) is closest to 0.78, so new students start on easier variants and move up as ratings rise — §3.1/§3.2 are explicit.
- 2026-10-14 — The challenge has its own seed derived from the attempt seed (`seed ^ 0x5bd1e995`) when it declares its own params — one stored seed reproduces both.
- 2026-10-14 — Circuit builder: elements occupy one grid segment; the battery is fixed down column 0 (+ top, − bottom) — simplest snap-grid model; solution netlists are auto-laid-out on the grid and verified by re-solving.
- 2026-10-14 — The `?debug=1` hook is compiled only when `import.meta.env.DEV` or the build mode is not `production` (dev, test, and the `build:e2e` mode), via a `define` constant so the Pages bundle contains none of the hook code — e2e runs against `vite preview` of that build; the Pages build has neither.
- 2026-10-14 — The challenge stage keeps the Facts panel in its sidebar — §2.2 says the Facts panel stays visible for the whole lesson.
- 2026-10-14 — Challenges also update the student's rating for the challenge's concept (difficulty = the variant's band, score per §7.5) — §3.2 selects the challenge variant by that concept's rating, so it should learn from the result.
- 2026-10-14 — Circuit-builder solutions may be `grid` edits on a `preset` circuit as well as netlists — meter-placement challenges start from a built circuit, which a netlist can't express.
- 2026-10-14 — Parts available in the palette but not yet placed read 0 in the check scope (`P_L2 = 0`) — feedback rules like "every bulb must light" must evaluate before the student places every part.
- 2026-10-14 — Transient-plotter sliders take an optional display `scale`/`unit` (μF, kΩ) while values stay in SI — check expressions stay unit-consistent.
- 2026-10-14 — phys2 U3 challenges use only the two tools §16.4 lists for the unit: capacitors (l7) use the transient plotter's C and V sliders for charge/energy goals — the circuit builder has no capacitor element.
- 2026-10-14 — `template` treats `{{{x}}}` as a TeX brace around `{{x}}` — needed for `\dfrac{{{R2}}}{…}` in content.
- 2026-10-14 — CI also runs the Playwright e2e suite before deploying — §17 requires e2e to pass in CI; the §6.3 workflow doesn't list it.
- 2026-10-14 — Review entries store the parameter seed they were last shown with, and review picks a seed whose parameters differ — §3.3 promises new numbers, which a random seed only gives 2 times in 3 with three param sets.
- 2026-10-14 — Review answers update concept/subject ratings and question history like lesson answers — the student's ability is the same whichever mode they answer in.
- 2026-10-14 — Concept ratings and misconception counts are keyed by id only, not subject-prefixed — §12's shape; ids are slugs chosen to be unique across subjects.
- 2026-10-14 — Export/import/reset live on the profile page; reset needs the word RESET typed, import shows a summary before replacing — §10.1 and §12.
- 2026-10-14 — Pyodide is pinned to 314.0.7 and loaded from cdn.jsdelivr.net inside a module Web Worker, only when Python code first runs — §4/§5 (pinned, CDN, lazy).
- 2026-10-14 — The code-runner "Check" always re-runs the tests first (an async `beforeCheck` hook on challenge modules) — results must belong to the code being checked.
- 2026-10-14 — code-runner `solutionScope` reports a full pass; `scripts/code-check.ts` separately runs every reference solution (JS in node:vm, Python via python3/python, falling back to Pyodide in Node) against all tests and the performance case — `solutionScope` must be synchronous and browser-safe.
- 2026-10-14 — Python reference solutions are batched into one subprocess per validation run — keeps `content:check` fast.
- 2026-10-14 — Challenge modules may define `withSolution` (Parsons needs the correct order to score a state) and `mergeSolution` (code-runner shows the solution in the student's current language).
- 2026-10-14 — The algorithm stepper's "solution" is `{ followTrace: true }`: the reference trace is generated from the input — §9.2 says the solution is the generated trace.
- 2026-10-14 — The stepper accepts exactly one correct action per step (e.g. ⌊(lo + hi)/2⌋ in binary search) — a single reference trace keeps the explanation of every wrong move precise.
- 2026-10-14 — Performance generators are built so brute force can't slip through: `sortedTwoSum` makes its pair unique by construction (values ≡ 0 mod 4 except the pair, ≡ 1 and 2) and places it in the middle half; `longestUniqueSubstring` cycles through a large character pool so the answer window is thousands long (brute force is O(n · L)); `rangeAdds` was added for the difference-array challenge.
- 2026-10-14 — The validator runs Python with `PYTHONIOENCODING=utf-8` — Windows Python otherwise decodes stdin in the ANSI code page and mangles non-ASCII test strings.
- 2026-10-14 — Lesson challenges that need more than one function keep one function per variant (dsa U2 L6: fixed window → variable window → variable window with a performance test; L7: range sums → with performance test → difference array) — the code-runner config has a single entry point per variant.
- 2026-10-14 — graph-manipulator also exposes `f(x)`, `fp(x)`, `A(x)` and `maxDev(lo, hi, c)` (largest |f − c| on [lo, hi], skipping points where f is undefined) and `Ax0` — the §16.1 ε-zoom and ε–δ challenges need "every point within ε", which the listed scalars can't express.
- 2026-10-14 — graph-manipulator `matchError` is the largest distance between the curve and the target at matching x (function mode) or t (parametric/polar), over the view or parameter range.
- 2026-10-14 — riemann-sum exposes `rule` as a number with constants `left`, `right`, `midpoint`, `trapezoid`, `simpson` in scope — mathjs can't compare strings with `==`, so checks read `rule == midpoint`. Simpson rounds an odd n up to the next even n, and `n` in scope is the n used.
- 2026-10-14 — series-explorer Taylor mode computes coefficients from symbolic derivatives (mathjs `derivative`) at the center — no hand-entered coefficients to get wrong.
- 2026-10-14 — graph-manipulator `view` bounds may be expressions in the controls (a zoom slider `w` in `[a − w, a + w]`) — §16.1's "zoom" challenge needs the window to shrink as the student closes in. Pressing anywhere on the plot moves the nearest draggable control there, so a control outside a zoomed view stays reachable.
- 2026-10-14 — The validator warns when a challenge's starting state already passes its check (code-runner excepted; its check needs a run) — a pre-solved challenge teaches nothing. It caught phys2 U3 L5, whose empty circuit satisfied every `near(…)` with all currents 0.
- 2026-10-14 — Challenge params that appear as coefficients in a displayed formula are integers — templates print 3 significant figures, so b = 1.5 would show b³ as 3.38 in a formula whose plot uses 3.375.
- 2026-10-14 — The content build adds to each misconception's `lessons` every lesson that tags it (after the hand-listed ones, in syllabus order) — the profile's "Revisit" links should reach every lesson that targets the misconception, and a hand-kept list drifts.
- 2026-10-14 — graph-manipulator `band` may also name controls (a student-placed line y = L) and is resolved per state.
- 2026-10-14 — **Spec v2 adopted** (interaction-first rework) during Phase 6 of v1. The phase sequence restarts at v2 Phase 1 on the existing codebase: the engine, storage, circuit solver, interactives and content tooling carry over; the lesson format, player and validator are rebuilt. v1 lessons (phys2 U3, dsa U1–U2, calc1 U1–U2 L1) move to `archive/v1-content/` as raw material and are rewritten in v2 format in their phases (phys2 U3 → Phase 3, dsa → Phase 5, calc1 → Phase 6). The v1 player is kept in `archive/v1-src/` for reference.
- 2026-10-14 — `src/challenges/` became `src/interactives/` with the §9 model/view split (`model.ts`, `view.tsx`); `ChallengeLogic` is now `InteractiveModel`, with `modes` and an optional `applySolution` that defaults to `solutionState`.
- 2026-10-14 — Question widgets validate their own kind-specific fields: the shared `QuestionSchema` is a loose object (common fields only) and each widget's `model.ts` schema checks the rest (§9.1). A kind without a model fails validation, so content can only use widgets that exist (§13.2).
- 2026-10-14 — Unit `checkpoint.items` is optional and defaults to 12 — §7.2 shows it per unit, §3.5 says 12–15.
- 2026-10-14 — Default concept `requires` links: a lesson's other concepts require its first concept, and a lesson's first concept requires the previous lesson's first concept. Hand-refined as each unit is written (phys2 U3 now matches §7.3's example).
- 2026-10-14 — Concept and misconception ids stay bare slugs in the content files and JSON; the app namespaces them as `<subject>/<slug>` (`nsId`) wherever they key progress (§7.3). Cross-subject `requires` already use the full form.
- 2026-10-14 — Path-map nodes and navigation for features not built yet (practice sets, checkpoints, hard mode, puzzle packs) show "Coming soon" via `FEATURES` in `config.ts`, rather than linking to pages that don't exist.
- 2026-10-14 — While a subject has no lesson files, its unused misconceptions are summarised in one validator warning instead of one per id.
- 2026-10-14 — Progress is stored as version 2 (the spec's `ProgressV1` shape) because version 1 was the pre-v2 store; the 1 → 2 migration keeps lesson results, subject ratings, misconception counts and settings, and drops v1 attempts, un-namespaced concept ratings and the Leitner review queue (spaced review is now the memory model).
- 2026-10-14 — `AttemptState` adds `sequence` (screen and inserted-step ids in play order), `skipped`, `firstInSubject` and `startedAt` to §12's fields; answer records add `correct`, `misconception` and `variant`. Lessons keep `lastOpenedAt` for "Continue lesson".
- 2026-10-14 — Mastery levels only rise; a fading concept shows "Needs review" (recall < 0.5) instead of dropping a level (§3.4).
- 2026-10-14 — The debug hook is `window.__fieldlyDebug` (the spec's `__stepwiseDebug`, renamed with the product) with `answerCurrent()`, `loadSolution()`, `setSeed()` and a `current()` helper. `answerCurrent()` fills the widget with a correct answer and the test still presses Check, so e2e exercises the real submit path. Every registration is guarded by `__DEBUG_HOOK__`, and `tests/unit/dist.test.ts` builds the production bundle and checks it contains no hook.
- 2026-10-14 — Placeholder interactives (Phase 2) say so on screen, and offer "Do it for me" on explore goals and hook reveals; a challenge whose interactive is a placeholder offers "Show solution" straight away (scoring 0), so a learner can finish the lesson honestly until the real view ships in Phase 3.
- 2026-10-14 — The hint ladder sits under the question rather than in the sidebar — on a phone the sidebar is far below the work, and hints belong next to it.
- 2026-10-14 — `match` uses a letter menu per left item (right items are lettered) instead of drag-and-drop — sides can be plots, and the menu works identically by mouse, touch and keyboard (§11). `order` and `categorize` use @dnd-kit with its keyboard sensor, plus ↑/↓ buttons and a per-card "Move to" menu.
- 2026-10-14 — Long explanations (4+ blank-line blocks) are staged: Answer and Why show first, then "Show next step" per block (§2.5). The Explanations tab always shows them whole.
- 2026-10-14 — `estimate` takes one attempt; its score is the band score, capped by the hint-tier score.
- 2026-10-14 — The confidence prompt (Settings, off by default) is asked when the learner presses Check, before grading — asking afterwards would reveal the result first. A confident mistake gets a highlighted explanation.
- 2026-10-14 — Challenge results update ratings like a graded step at the variant's difficulty; "Show solution" scores 0 and sets `freshNext`, like a tier-3 hint. A feedback rule's misconception is counted each time it fires.
- 2026-10-14 — Challenge stars: ★ solved, ★★ without hints, ★★★ also at or under every `par` value in the check scope (§9.5 applied to lesson challenges). The circuit check scope adds `parts` (resistors + bulbs placed) for `par: { parts: n }`.
- 2026-10-14 — Explore `ask`/`predict` answers, the hook prediction and the recap self-explanation are stored in `attempt.answers` under `<screen>#t<i>`, `<screen>#predict` and `<screen>#explain`; worked-screen progress (steps shown, blank values, tries, faded count) is stored in `attempt.explore[screen]`. Everything a screen shows comes from the attempt, so resume and the read-only history view need no extra state.
- 2026-10-14 — A concept first met in a lesson records the subject rating it started from as `ratingAtLessonStart`, so the recap can show rating changes for every concept in the lesson.
